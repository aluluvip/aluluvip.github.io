折腾篇：openGym —— 一个 docker compose up 起来的健身记录，数据全留在自己硬盘

折腾篇：openGym —— 一个 docker compose up 起来的健身记录，数据全留在自己硬盘

项目地址：https://github.com/DuarteSantos8/openGym ｜ 许可：AGPL-3.0（动作素材另算） ｜ Star：约 2.3 万（22,924，2026-11-20 查询） ｜ 最新版本：v1.4.5（2026-11-14 发布）

先说结论：如果你受够了把训练数据存在别人的服务器上、随时可能被订阅卡住，openGym 是目前自托管健身记录里完成度最高的一档。 它不是玩具：5600 多个动作库、进步规则、肌肉分布图、Apple Watch 与 Wear OS 双端、passkey 登录、离线 PWA 都齐了，而且 docker compose up -d 一条命令就能跑起来。

但它也有几个必须先看清的前提：动作图片和动画是第三方版权素材、并不随 AGPL 一起开放；手机上要用 passkey 同步必须给自己配 HTTPS 和域名；Google Play 版还在封闭测试，Android 目前主要靠 APK。这几点决定了它适合谁——文末单独列。

一、它跟 Keep、Strong 最根本的区别：数据是一个你能拷走的文件夹

多数健身 App 的数据活在开发者服务器上：账号在云端，历史在云端，公司一关或者一改收费策略，你的训练记录就跟着没。openGym 反过来——它跑在你自己的机器上，所有东西落在宿主机的 ./data 目录， backup 就是把这个目录打包：

文件 装的是什么
db.json 用户档案与 passkey 公钥
state-<user>.json 每个人的训练计划、训练记录、体重、设置
db.json.bak 上一份完好的 db.json，主文件坏了自动回退
audit.log 登录与管理操作日志（默认不记 IP）
secret 会话 Cookie 的签名密钥

这套设计带来两个很实际的好处。第一，导出就是复制文件，不需要在 App 里点「导出-上传-下载」；第二，它支持从 Strong、Hevy、FitNotes（CSV 或 API key）以及 Apple Health 的体重导出导入，换过来不用从零开始记。数据想再搬走时，也能整体导出成一个 JSON，或者把训练和身体数据导成 CSV 表格。

提醒一句：passkey 的私钥永远不离开你的设备安全芯片或密码管理器，服务器只存公钥。这意味着别人的服务器拿不到你的生物识别信息，但也意味着 RP_ID 和 ORIGIN 配错就登不上——这是这个项目 issue 区最常见的问题。

二、训练这条链它做得很细：计划 → 记录 → 进步 → 肌肉分布

计划：一周七天排训练，动作库 5600 多个，每个动作带动画演示，能按器械筛选、在身体图上按肌肉浏览。内置四套入门计划（推/拉/腿、上/下肢、全身、5×5），加载后就是普通可编辑的常规计划，不是只读模板。不想按星期走，也可以用 A/B/C 轮换——下一次训练就是「还没做过的下一个」，周末打乱了也不影响。超级组、热身组、递减组、保持时间（平板支撑、悬垂、农夫行走）、按时间计的有氧，都能排。

记录：当天训练自动开始，重量从上一次自动带入，组间休息计时器在跑，新纪录（PR）当场识别。每组可以单独设次数、重量、RIR/RPE 努力程度；左滑删除（带撤销）、右滑复制；器械被占了，预设的替代动作一键换上并保留这组次数。杠铃片重量会按你各自的健身房配置算——你有几个场馆，就能各自维护一套杠铃片、哑铃和器械配重，手机走进哪个馆就切到哪个。

进步：这是我认为它最像「正经训练工具」的部分。每条计划或每个动作可以单独设进步规则——线性加重、Greyskull LP、在可见次数区间里双重递进、三重递进（先次数、再组数、再重量），或者单纯加时间。每条目标都会解释为什么是这个数，少做的次数不会自动加重，卡住会触发减载周（deload）。另有估算 1RM 曲线、结构平衡比例（Poliquin / Thibaudeau / ATG）和整年的活动热力图。

肌肉分布：三种模式看同一张肌肉图——练去的容量落在哪、哪些还在恢复、哪些根本没练到。这个视图比单纯记「今天卧推 4 组」有用得多，能直接看出自己是不是一直在练胸和二头。

三、装起来到底有多简单，以及架构长什么样

打开 http://localhost:8080，点 Create profile 就能用。动作动画已经打进镜像，不用另外下载，宿主机也不需装 Node。镜像同时发到 ghcr.io 和 GitLab Registry，amd64 / arm64 都有；想从源码构建就跳过 pull 改跑 --build。

架构很克制：前端是 React 19 + Vite，构建成静态文件；API 是一个 node:http 服务，只依赖 @simplewebauthn/server、web-push 和 undici 三个包；nginx 把页面和 /api 收在同一个 origin 下——passkey 要求同 origin，这一点是刻意设计的。训练逻辑（进步规则、1RM、历史回读）是纯函数，旁边就放着单元测试。

同步机制值得单独说：每个档案的数据是一份带版本号的文档，设备保存时带上自己上次看到的版本；如果期间别人写过，服务器拒绝并返回当前文档，设备合并后重试。每处改动都带自己的时间戳，细到单个设置项或计划字段，合并时保留最新的那次编辑，删除也保持删除。断网或退出登录不会丢掉还没同步的内容，离线时 App 会显示横幅。

四、手机和手表不是附赠品，是同一套系统的另一半

同一套代码用 Capacitor 打包成手机 App，可以完全脱离服务器单机用（数据只留手机、不用账号），也可以连上你的服务器同步。获取方式按设备分：

平台 怎么装 备注
浏览器 opengym.ch 的 Live demo 真实 App 加示例数据，装之前可先试
自托管 Web docker compose up -d 后访问 8080 可加到主屏幕当 PWA，离线可用
iPhone / iPad App Store（含 Apple Watch App） 全球区上架
Android 最新 release 的签名 APK，或官网下载 分 Standard / Plus / HD 三种体积
Google Play 封闭测试中 需加入测试组并报名，满 14 天后开放
Wear OS 手表 随 Play 测试发放的 Beta 暂未正式发布

Android APK 的三个版本差别在于动作动画的分辨率：Standard（180 px，约 315 MB）、Plus（240 px，约 424 MB）、HD（360 px，约 760 MB）。APK 自带 .sha256 校验文件，和 Play 版共用同一个签名密钥，可以在两者之间切换而不丢数据。

手表端在 v1.4.5 刚做过一次大改：Apple Watch 与 Wear OS 统一了设计，数字表冠转动调重量/次数，整屏休息倒计时、每组心率、锁定按钮防误触都齐了，还能在表盘上放复杂功能。手表和手机上的组是联动的——在 iPhone 上勾掉一组，手表会自动跳到下一组；手机上暂停的休息计时，手表上也会停住。

五、开箱就有，但默认关着的两样东西

项目把一些「容易被人说是噱头」的功能默认关掉，这点我认可：

  • AI 教练：默认关闭，打开后能起草一周计划、根据你实际记录提调整建议、回答训练问题，但每一处改动都要你确认。它跑在你自己的服务器或手机上，用你自己的 key（Anthropic / OpenAI / Gemini / 任何 OpenAI 兼容端点，包括 Ollama）。默认安装里没有任何 AI 调用，不需要 API key。
  • MCP 服务：让 Claude Desktop 这类助手查询训练历史、把口述的训练记进去，本地运行，不在 Docker 镜像里。

另外有个叫 Modules 的开关，能在设置里把 Body、Health、Motivation、Coach、节日主题等整块功能关掉，界面里彻底消失，但数据一条不删。只想「记录训练」的人可以把它砍成极简版。

项目自述里坦白说大量代码、测试和文档是用 Claude Code 起草的，但由人决定和发布，训练逻辑有单元测试、CI 跑三套测试。这段放在 README 里，算是把话说在前面了。

六、已知的坑，以及适合谁 / 不适合谁

动作素材不是 AGPL 的。 openGym 自己的代码是 AGPL-3.0，但动作图片和动画版权归 Gym visual（© Aliaksandr Makatserchyk），授权范围仅限在 openGym 里使用：仓库和自托管服务器上是 180 px，更大尺寸只在 App 包里。非商业 fork 可以原样保留并带上声明，其他用途得自己去 gymvisual.com 买授权。想基于它做商业产品的人，这一条比 AGPL 本身更要命。

AGPL 的网络传染性。 你改了代码并作为网络服务提供给别人，就必须把改过的版本也按 AGPL 开源。自己家用无所谓，拿来二次开发做 SaaS 要先想清楚。

远程用 passkey 必须配 HTTPS。 本机 localhost 玩没问题，但要从手机连、要用 passkey，就得有域名 + HTTPS，并在 .env 里把 RP_ID 和 ORIGIN 配成一致。项目文档给了 Cloudflare Tunnel、Caddy、Traefik、nginx 的教程，也有局域网 HTTPS 和 Mac + Tailscale 的专门指南——这说明它不是「开箱就能手机连」，得动点手。

Android 与手表的成熟度有差。 Google Play 版仍在封闭测试（需要 12 名测试者满 14 天），Wear OS 版还是 Beta。只想从正规商店稳定更新的人，现在会有点别扭。

适合谁：想彻底掌控自己训练数据、有台 NAS 或常开小主机、愿意花半小时配 Docker 和 HTTPS、认真做力量训练并需要进步规则与肌肉分布的人；以及 iPhone + Apple Watch 用户，这端的完成度目前最高。

不适合谁：只想随手记几组、不想碰服务器和域名配置的人（浏览器 demo 或普通健身 App 更省事）；想拿它做商业健身产品又不打算处理动作素材授权和 AGPL 的人；只认 Google Play 稳定版、不装 APK 的纯 Android 用户。

版本节奏是每 1 到 2 周一个 release，v1.4.5 在 2026-11-14 发布，重点在全平台手表重设计、Garmin 接入、循环训练、实时小组件、可真正执行动作的 Coach、教练与场馆、OIDC 和社区动作库。它是那种「你部署一次，然后隔两周就发现多了点东西」的项目——这也是自托管最舒服的状态。
